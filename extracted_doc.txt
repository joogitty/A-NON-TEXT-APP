The connection dance

Both devices generate an ephemeral X25519 key pair and gather local ICE candidates (their LAN IP addresses or mDNS .local names).

Each device displays a QR code containing a compressed signaling payload (~55–100 bytes). A modern approach called QWBP (QR‑WebRTC Bootstrap Protocol) fits this into a single scannable code by stripping the bulky SDP down to identity + ICE candidates + DTLS fingerprint.

They scan each other (bidirectional). After the scan, each side has enough data to synthesize the full SDP locally — no server, no internet, no STUN/TURN required.

Primary path: The browser’s ICE engine tries to connect using those local host candidates. On the same LAN this usually succeeds in under a second, opening a DataChannel that can move 1–10 Mbps — plenty for images, voice notes, and even chunked video.

If the DataChannel fails to open (e.g., devices are not on the same network), the app falls back to Quiet.js on the ultrasonic profile (~19 kHz, nearly inaudible). Throughput is low (~500–3,000 bps), but it is enough for text, small JSON, or a tiny “join my hotspot” payload containing an SSID and password. Once the hotspot is joined, the app can retry Step 4 and upgrade to the high‑speed WebRTC channel.

Critical implementation details

1. WebRTC without STUN/TURN on a LAN

On a local network you can create the peer connection with an empty ICE server list:

const pc = new RTCPeerConnection({ iceServers: [] });

The browser will still generate host candidates (your 192.168.x.x or fe80::... addresses). Modern browsers may mask these as mDNS names like 3db1cebd...local for privacy, which works fine as long as both devices are on the same LAN and multicast is not blocked by the router.

One caveat: if the device has no active network interface at all (e.g., Wi‑Fi is off and there is no hotspot), some browsers will not generate any host candidates. In that case the fallback to audio is essential.

2. Quiet.js audio fallback

Quiet.js is a JavaScript binding for libquiet that uses the Web Audio API to send and receive data via sound.

// Transmitterconst transmitter = Quiet.transmitter({ profile: 'ultrasonic' });transmitter.transmit(Quiet.str2ab("Hello offline world"));// Receiver  const receiver = Quiet.receiver({ profile: 'ultrasonic' });receiver.onReceive = (payload) => {  console.log(Quiet.ab2str(payload));};

3. QR signaling without a server

Traditional WebRTC tutorials assume a signaling server. You do not need one. The “serverless webrtc” pattern (dating back to 2013) proves that copying the SDP offer/answer manually — or via QR — is sufficient.

For a production app, compress the signaling data: - Extract only: ice-ufrag, ice-pwd, dtls fingerprint, and host candidates. - Encode with Base45 or a custom binary‑to‑QR scheme. - Use QR error‑correction level L (low) to maximize data density, since the payload is tiny.

async function scheduleDeletion(messageId, ttlMs) {  setTimeout(async () => {    const tx = db.transaction(['messages', 'mediaRefs'], 'readwrite');    const msg = await tx.objectStore('messages').get(messageId);    if (msg?.mediaRefs) {      for (const ref of msg.mediaRefs) {        await root.removeEntry(ref.fileName); // OPFS purge      }    }    await tx.objectStore('messages').delete(messageId);  }, ttlMs);}

For reliability across tab closes, register a Service Worker with periodic-background-sync (where supported) or simply run the sweep every time the app wakes up.

5. Anonymity model

No accounts: Generate ephemeral X25519 keys per session using crypto.subtle.generateKey({ name: 'X25519' }, true, ['deriveBits']).

No phone numbers / email: Identity is the public key fingerprint.

Trust through proximity: The QR scan is the authentication step. An attacker must physically photograph both QR codes to MITM the exchange.

Forward secrecy: Discard keys after the session ends. Nothing is ever uploaded.
